# V2: Conversation-Aware Issues

Target: Mid/Late March 2026

## Core Abstraction

- **ConversationSource trait**: Define `ConversationSource` trait mirroring the `Forge` pattern — trait in `src/conversations/mod.rs`, common types (`Conversation`, `ConversationDetail`), enum dispatch. Conversation has: id, start/end timestamps, files touched, tool invocations, token counts.
- **Claude Code implementation**: First `ConversationSource` impl. Read and normalize `~/.claude/projects/` JSONL files. Lives in `src/conversations/claude_code.rs`.

## Conversation-to-Issue Linking

- **Anchor conversations on `isq start`**: When `isq start <issue>` runs, record the active conversation ID and issue in SQLite. This is the join between issues and conversations.
- **Schema migration for conversation links**: Add tables for conversations and conversation-to-issue mappings. Same `PRAGMA user_version` migration pattern.
- **Detect conversation-issue links heuristically**: Fall back to branch name or issue ID mentions in conversation when no explicit anchor exists.

## CLI

- **`isq conversations <issue>` command**: List all conversations linked to an issue — timestamps, duration, files touched. Supports `--json`.
- **`isq conversations <issue> --export`**: Dump full conversation content for an issue in a portable format. This is the data an agent uses to reason about what happened.
- **`isq metrics` command**: Show cycle time (first prompt → PR merged), conversation count per issue, and churn signals. Supports `--json`.

## Skill

- **Conversation retrieval skill**: Skill doc in `.claude-plugin/skills/` that teaches agents how to use `isq conversations` to retrieve conversation history for issues. No opinion on what the agent does with the data.

## Daemon

- **Conversation index sync**: Daemon periodically indexes new conversations and updates links. Same pattern as forge sync — local-first, SQLite is source of truth.
